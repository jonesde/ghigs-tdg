# Chrithmath Theme — Plan

A new map theme: Christmas with puns and dad jokes. Enemies are bots based on traditional
toys; towers fire candy, each based on a real Christmas candy tradition. Three regions map
to Christian traditions: Western (Western Europe + American), Southern (Australian + Middle
Eastern, the non-winter exception), Eastern (Eastern Europe, Orthodox branches).

## 1. Theme identity & files

- **Label**: "Chrithmath" (Christmas × math). **id**: `chrithmath`, **file**:
  `src/render/themes/data/chrithmath.json`.
- **Ships a `maps` catalog override** (like Aftermath): its own 36 level configs + 12
  progressive variants, so the world's levels are distinct from both the default catalog and
  the Aftermath catalog (§7).
- Art ships generated by a new Python script `src/render/themes/scripts/gen_chrithmath_theme.py`,
  modeled on `gen_aftermath_theme.py` (2401 lines) — same frame contracts, same validation
  style, contact sheet to `tmp/chrithmath-contact.html`.
- **Menu background sidecar**: `src/render/themes/data/chrithmath-menu.json`, holding
  `{ "menuBackground": "<svg…>" }` and nothing else. The main-menu world card paints from the
  sidecar rather than loading the whole theme (§8, already built for the two shipped worlds — the
  chrithmath file is still owed).
- Registration: three adjacent lines in `src/render/themes/index.ts` under the
  `/* ======= ADD MAP THEMES HERE ======= */` marker at `:139` — one `MAP_THEME_MANIFEST`
  entry, one `registerThemeLoader`, one `registerMenuBackgroundLoader`.
- Every name is a single string in a `TOWER_META`/`ENEMY_META` table in the script, so names,
  colors, glyphs and shapes are one-line swaps.
- **No description text, and none is possible**: `RawMapThemeSchema`
  (`src/content/schemas/theme.ts:120-130`) has no `description` field and Zod strips unknown
  keys, so a `description` in the JSON would be silently dropped. Puns live only in
  `name`/`icon`/`color` and the art.

## 2. World concept

A Christmas where the defense is candy and the attackers are toys that came to life out of
the toy box. **Enemies are toy bots** — all nine map to a traditional toy. **Towers are candy
traditions** — each fires the candy of a real Christmas custom. Spawns are a **toy-box hatch**,
caches are **gift boxes**, the boss package is **Santa's sack**.

## 3. Regions (3)

### Field fills — settled before any tile is drawn

Height is a gameplay input (`terrainHeightBonusPct`, `terrainHeightRangeBonusPct` in
`economy.json`, plus the height-shaded 5×5 block previews in `ProgressivePlacement.vue`), so
the four steps must read as a ramp. Two shipped-theme rules govern it, both measurable:

- **The path field is the darkest value in its region.** Measured in `the-aftermath.json`:
  path luminance 0.013 / 0.018 / 0.016 against a darkest terrain of 0.077 / 0.126 / 0.048.
  Path legibility is the most gameplay-critical read on the board; character comes from hue
  and motif, never from making the path light.
- **terrain1 → terrain4 luminance is monotonically non-increasing** — the rule
  `tests/unit/map-theme.test.ts:869-881` enforces, and it reads only the first `fill="#…"` hex
  (the field rect).

| Region | path | terrain1 → terrain4 | span | min adjacent step | path margin over darkest terrain |
|---|---|---|---|---|---|
| 0 Yule Vale | `#2f3a44` (0.040) | `#eef3f8` (0.891) → `#c8d6e2` (0.659) → `#94a9bd` (0.383) → `#5c7186` (0.158) | 0.732 | 0.225 | 0.118 |
| 1 Sunspice Coast | `#2a2016` (0.016) | `#e8d6ae` (0.683) → `#bd9a6b` (0.350) → `#6d7a4e` (0.177) → `#463c33` (0.048) | 0.635 | 0.129 | 0.032 |
| 2 Icon Snows | `#252b3e` (0.025) | `#dfe6f2` (0.787) → `#a8b6cc` (0.461) → `#6e7f9e` (0.210) → `#39435c` (0.057) | 0.730 | 0.153 | 0.032 |

(relative luminance, same formula as `relativeLuminanceOfChannels` in
`map-theme.test.ts:807-814`; Aftermath's spans are 0.411 / 0.544 / 0.566 and its smallest path
margin is 0.032.)

Characters, with the height read intact:

- **Western**: fresh snow → snow under fir shadow → deep drift → fir thicket. Path is packed
  snow **in tree shadow** (`#2f3a44`), with footprint stamps as the motif.
- **Southern**: pale sand → cracked earth → olive grove → shadowed rock coast. Path is shaded
  sandy track (`#2a2016`). **No snow anywhere in this region's art.**
- **Eastern**: pale blue snow → steel blue → deep blue → near-midnight with gold candle
  specks. Path is packed blue-white snow in deep shadow (`#252b3e`).

A new generator validator `validate_region_palette()` mirrors `relativeLuminanceOfChannels` and
asserts, per region: monotonic non-increasing terrain, path strictly darker than every terrain
kind, span ≥ 0.4, path margin ≥ 0.02, min adjacent step ≥ 0.10. Every rule above holds with
margin.

### Tiles (15 kinds × 3 variants = 45 tile images)

- Variant 0 is **hand-drawn per kind** — 15 authored tiles (the Aftermath equivalent is
  `rustbloom_tiles` / `sand_tiles` / `ash_tiles`, `gen_aftermath_theme.py:1260, 1346, 1431`).
  Variants 1 and 2 come from the seeded `tile_variant` construction, one seed per
  region/kind/variant (`tile_seed = 7000 + region*100 + kind*10 + variant`, `:1148-1151`), so a
  rerun is byte-identical.
- Motif colors are ramp siblings read off the table above — the Aftermath construction
  (`gen_aftermath_theme.py:1517-1556`). Each variant is field fill, three interior drifts, a
  stain, a pebble, and three edge-crossing smears.
- **One edge convention for the whole theme**: keep the Aftermath route — three of four edges
  crossed by smears at `EDGE_MOTIF_OPACITY_RANGE = (0.24, 0.28)`, so rotated neighbours read as
  one ground tone. This works here only because the ramp steps above are wide (min 0.129): a
  0.26-alpha sibling smear still registers against the field. Nothing else structural within 3px
  of a cell edge, and no mark under ~2px (rotation turns it into a scratch —
  `MapThemeHowTo.md:203`).
- The first `fill="#…"` in every tile must be the full-bleed 36×36 field rect (`fieldFill.ts:7-11`
  takes the first match only); the generator's `first_field_fill`
  (`gen_aftermath_theme.py:2150-2159`) enforces the `<rect width="36" height="36">` shape. Tile
  byte budget `TILE_BYTE_MAX = 1200`.

### Region maps (3 images + 16-node layouts each)

Node positions along a village path per region (steeples / coast + lighthouse / onion-dome

## 8. Menu card preview decoupling — **DONE**

**Problem.** `MainMenu.vue`'s mount hook used to call `ensureThemeLoaded` for every manifest theme,
purely to paint the card background. A third theme would have added ~480 KB (`the-aftermath.json`
is 482,601 bytes) of JSON downloaded, parsed and Zod-validated on every cold main-menu load, to
render one image.

**What landed.**

| Piece | Where |
|---|---|
| `MenuBackgroundSource` / `MenuBackgroundLoader` types | `src/render/themes/index.ts:120-128` |
| `MENU_BACKGROUND_LOADERS`, `registerMenuBackgroundLoader`, `getMenuBackgroundLoader` | `src/render/themes/index.ts:149-157` |
| Both registrations, each directly below its theme loader | `src/render/themes/index.ts:173-179` |
| `normalizeMenuBackground` (exported; `normalizeThemeImages` now calls it too, so one code path) | `src/render/themes/normalize.ts:147-152` |
| `menuBackgrounds` cache + `ensureMenuBackgroundLoaded` | `src/stores/mapTheme.ts:26, 109-125` |
| Default world's preview seeded from the already-loaded default theme | `src/stores/mapTheme.ts:39-42` |
| Mount hook: `ensureActiveTheme` + per-theme preview fetch; card reads `menuBackgrounds` | `src/components/MainMenu.vue:22-30, 164` |
| Sidecar writer + read-back drift check | `gen_theme_images.py` — `MENU_BACKGROUND_PATHS`, `write_menu_background_sidecar`, `verify_sidecar_matches_theme` |
| Sidecars for the two shipped worlds | `data/default-menu.json` (6,313 B), `data/the-aftermath-menu.json` (14,516 B) |

**Measured result** (`npm run build`, each is its own chunk): the unselected Aftermath world went
from a 515.16 kB (41.14 kB gzip) theme chunk to a 13.20 kB (2.72 kB gzip) sidecar chunk. With
Chrithmath added that is another ~14 kB instead of another ~515 kB.

**Design notes.**

- One sidecar per theme, `data/<id>-menu.json`, content `{ "menuBackground": "<svg…>" }`. Three
  ship. `import.meta.glob` was rejected: it appears nowhere in this repo (`src/`,
  `vite.config.ts`) and `default-map-theme.json` / `the-aftermath.json` do not follow a
  `*-menu.json` naming rule, so it would need a convention invented for it.
- The theme JSON **keeps** its own `menuBackground` — `RawMapThemeSchema` requires nothing here,
  but the game screens and `normalizeThemeImages` read it. The sidecar is a **duplicate**, which is
  the whole risk: `gen_theme_images.py` now writes both in one pass and reads the sidecar back to
  assert equality, and `gen_theme_images.py` round-trips all four data files byte-identically.
- A world with no registered sidecar logs a warning and leaves its card background empty rather
  than failing the menu — the card is decoration. `default-menu.json` is still reachable as the
  fallback (the default theme's own copy is normally seeded instead, so its 5.67 kB chunk is
  usually never fetched).
- The full-bleed background (`MainMenu.vue:20`) and the run path
  (`SvgGameRoot.vue:116, 1055` reads `activeTheme`) still need the selected world loaded in full,
  so the mount hook calls `ensureActiveTheme` (`mapTheme.ts:146-158`) — cached and idempotent.
  `playThemeHighestMap` (`MainMenu.vue:63-76`) already awaited `loadActive` on a world switch;
  unchanged.
- `ensureThemeLoaded` now has no caller in `src/` (tests still exercise it). Left in place: it is
  an exported, tested store API, and deleting it is not part of this change.

**Deferred to step 1**, because the theme JSON does not exist yet: the third
`registerMenuBackgroundLoader` line for `chrithmath`, the `chrithmath` sidecar in
`MENU_BACKGROUND_PATHS` / `THEME_PATHS`, and `gen_chrithmath_theme.py`'s `validate_theme`
sidecar-equality assertion.

**Tests** (`npm run check`: 2035 tests / 117 files, all green):

- `tests/unit/map-theme.test.ts` — six new store tests: the sidecar loads without touching
  `loadedThemes`; it equals the theme's own `menuBackground`; it caches; an unregistered id warns

- `tests/unit/components/main-menu.test.ts` — the preload block now fills **both** caches, and two

## 11. Implementation steps

0. **Seed pre-flight — DONE, all seeds kept.** A throwaway spec ran the
   `assertCatalogInvariants` twin (`tests/unit/map.test.ts:733-814`) over all 36 levels with the
   §7 seeds, and a second throwaway swept the site quota of all 36 boards plus all 12 progressive
   variants × 3 salts (the §9 check) before any art existed. Both passed on the first roll, so the
   seed tables in §7 stand as written. Both throwaways were removed; the only surviving change is
   the `fillOpeningBoard(index, catalog?)` signature that §9 needs. Swap the inline literals for
   `resolveThemeMaps(chrithmathRaw.maps)` imports when the generator lands the theme JSON.
1. **`gen_chrithmath_theme.py`** skeleton (~2,400 lines, modeled on
   `gen_aftermath_theme.py`): identity tables (`TOWER_META` / `ENEMY_META` with the §4/§5
   values including durations), the §7 `CHRITHMATH_MAP_LEVELS` / `CHRITHMATH_PROGRESSIVE_VARIANTS`
   tables and `maps_override()`, `build_theme()`, `write_theme()` with the
   `collapse_layout_lines` / `collapse_maps_lines` passes that keep reruns byte-identical,
   `contact_sheet()`, and `validate_theme()` covering: identity (id/label + every
   name/color/icon/shape/duration), frame counts (tower 3 + walk-1-equals-rest; enemy 8/3/3),
   `validate_region_palette()`, 3 variants + one shared field fill per tile kind, tile byte

## 12. Assumptions

- Region ids: 0 = Western, 1 = Southern, 2 = Eastern. This pins the gem pairing, not just the
  art: `MAP_GEM_MULTIPLIERS` (`src/content/data/economy.json:14`) is a 36-entry array indexed
  `regionId * 12 + level - 1` (`ProgressiveMap.ts:164-166`, `MapSelect.vue:88,106`) holding
  `[1×4, 2×4, 3×4, 4×4, 5×4, 6×4, 7×4, 8×4, 10×4]` — so region 0's maps pay the 1-3 band,
  region 1 the 4-6 band, and region 2 **7, 8 and 10** (there is no 9). The values are
  theme-invariant (the override never touches economy), but which Christmas region carries the
  low/mid/high band is a deliberate choice: Western pays least, Eastern pays most.
- All gameplay untouched — the theme is visuals-only; the maps override changes layouts (seeds),
  not balance.
- Names, colors and glyphs in §4/§5 are proposals; they are one-line edits in the generator's
  identity tables. The §3 palette table, by contrast, is **settled** — changing a field fill
  means re-running `validate_region_palette()`.
